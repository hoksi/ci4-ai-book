# 14장. 마무리

## 지금까지 만든 것

1장에서 빈 CI4 프로젝트로 시작해서, 13개 장을 거치며 이런 걸 만들었습니다.

**1부 — 기초**
- 라우팅/컨트롤러로 "AI 게시판" 뼈대
- extend/section 레이아웃
- 마이그레이션/Model/시더로 DB 연동, `allowedFields`와 소프트 삭제
- Validation으로 입력값 검증

**2부 — AI 기능**
- CURLRequest로 외부 API(Groq) 연동 기초
- 대화 맥락이 이어지는 챗봇 (무상태 LLM을 상태 있는 것처럼 보이게 만드는 법)
- 3단계 스팸 필터 — "저렴한 방법으로 먼저 거르고, 애매한 경우만 AI에게" + 사람이 최종 검토하는 human-in-the-loop
- 임베딩 없는 키워드 기반 RAG 문서 검색봇
- Groq 스트리밍 응답을 SSE로 실시간 중계하기

**3부 — 실전 다듬기**
- `CURLOPT_FAILONERROR`의 함정과 AI 쿼터 초과(429)를 안전하게 처리하는 법
- AI의 마크다운 응답을 안전하게(이스케이프 우선) HTML로 렌더링하기
- php-cli가 막힌 공유 호스팅에 git 기반으로 배포하기

이 순서 자체가 하나의 패턴입니다 — **먼저 동작하게 만들고(1~10장), 그다음 안전하고 견고하게 다듬는다(11~13장).** 처음부터 모든 에러 케이스와 보안을 완벽하게 고려하려 하면 아무것도 완성하지 못합니다. 일단 동작하는 걸 만들고, 실제로 겪은 문제를 하나씩 고쳐나가는 게 더 현실적입니다 — 이 책의 많은 챕터가 실제로 그렇게 쓰였습니다.

## 반복해서 나온 설계 원칙들

장마다 새로운 기능을 다뤘지만, 몇 가지 원칙은 계속 반복해서 등장했습니다.

- **외부 서비스가 실패해도 핵심 기능은 멈추지 않게 한다** (8장 StopForumSpam, 6장 API 키 누락 처리)
- **모든 요청에 AI를 쓰지 않는다** — 저렴한 방법으로 먼저 거르고, 정말 필요할 때만 AI를 호출한다 (8장, 9장)
- **AI 출력은 신뢰할 수 없는 외부 입력으로 취급한다** — 이스케이프 먼저, 그다음 가공 (12장)
- **판단이 불확실한 영역엔 사람을 끼워 넣는다** — AI가 전부 결정하게 하지 않는다 (8장)
- **설정값(모델명, API 키)은 코드가 아니라 .env/Config로 분리한다** (6장)

이 다섯 가지는 이 책에서 다룬 Groq/CI4 조합을 넘어서, AI 기능을 어떤 스택에 붙이든 그대로 적용됩니다.

## 더 만들어볼 수 있는 것들

여기서 멈추지 않는다면, 이어서 시도해볼 만한 방향들입니다.

- **11장의 에러 처리 패턴을 7~9장 전체에 일관되게 적용하기** — 이 책에서는 각 장의 핵심에 집중하기 위해 의도적으로 미뤄뒀습니다. 직접 챗봇/스팸필터/검색봇 코드에 `http_errors => false` 패턴을 적용해보세요.
- **9장의 키워드 검색을 임베딩 기반 벡터 검색으로 교체하기** — 문서량이 많아지거나 의미 기반 검색이 필요해지면 다음 단계입니다.
- **8장의 스팸 판정 로그를 모아서, 오탐/미탐 패턴을 분석하는 대시보드 만들기**
- **10장의 스트리밍에 에러 이벤트(`event: error`) 추가하기** — 스트림 도중 Groq가 실패하면 클라이언트에 알려주는 처리가 실전에는 필요합니다.
- **여러 AI 기능이 쌓이면서 중복되는 Groq 호출 코드를 서비스 클래스로 통합하기** — 지금은 챗봇/스팸필터/검색봇이 각자 Groq를 호출하는 코드를 조금씩 중복해서 가지고 있습니다.
